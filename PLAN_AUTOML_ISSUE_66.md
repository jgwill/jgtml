## 1. Objective

To develop a set of Python utilities that automate the end-to-end workflow for training, deploying, and monitoring Vertex AI AutoML models for the `jgtml` project. This includes handling the three distinct dataset types generated by `vertex_ai_data_transformer_v2.py`: Regression, Classification, and Forecasting.

## 2. Scope

The utilities will cover:
*   Programmatic launch of AutoML training jobs for each dataset type.
*   Programmatic retrieval of predictions from deployed models.
*   Basic monitoring of training job status and evaluation metrics.

**Project ID:** `top-moment-465521-v9`

## 3. Tools & Technologies

*   Python 3.x
*   Google Cloud Vertex AI SDK (`google-cloud-aiplatform`)
*   `gcloud` CLI for authentication and initial setup.

## 4. Proposed Utilities

We will develop the following Python scripts:

### 4.1. `launch_automl_training.py` (Unified Launcher)

This script will be a generalized launcher capable of initiating AutoML training jobs for Regression, Classification, or Forecasting based on input parameters.

*   **Purpose:** To submit new AutoML training jobs to Vertex AI.
*   **Inputs:**
    *   `--dataset-gcs-uri`: GCS path to the input CSV dataset (e.g., `gs://your-bucket/data_forecasting_mz.csv`).
    *   `--model-display-name`: A unique name for the trained model.
    *   `--model-type`: `regression`, `classification`, or `forecasting`.
    *   `--target-column`: Name of the target column (e.g., `target` for regression/forecasting, `target_class` for classification).
    *   `--time-column` (for forecasting only): Name of the timestamp column (e.g., `Date`).
    *   `--time-series-identifier-column` (for forecasting only): Name of the series identifier column (e.g., `time_series_identifier`).
    *   `--forecast-horizon` (for forecasting only): Number of future periods to predict.
    *   `--context-window` (for forecasting only): Number of historical periods to consider.
    *   `--optimization-objective`: The metric to optimize (e.g., `RMSE`, `MAE`, `AU_PRC`).
    *   `--feature-definitions`: A JSON string or path to a JSON file defining column types (e.g., `{"mfi_str": "categorical", "zcol": "categorical"}`). This will be crucial for correctly mapping `mfi_str` and `zcol` as categorical features.
*   **Core Logic:**
    1.  Initialize `aiplatform.init(project='top-moment-465521-v9', location='us-central1')` (or appropriate region).
    2.  Load or create the `TabularDataset` (for regression/classification) or `TimeSeriesDataset` (for forecasting) from the GCS URI.
    3.  Dynamically configure the `AutoMLTabularTrainingJob` or `AutoMLForecastingTrainingJob` based on `--model-type`.
    4.  Apply transformations based on `--feature-definitions` (e.g., `{"categorical": {"column_name": "mfi_str"}}`).
    5.  Run the training job and print the job ID and console link.

### 4.2. `make_predictions.py`

*   **Purpose:** To obtain predictions from a deployed AutoML model.
*   **Inputs:**
    *   `--model-id` or `--endpoint-id`: Identifier for the deployed model or endpoint.
    *   `--input-data-gcs-uri`: GCS path to the new data for prediction.
    *   `--output-gcs-uri`: GCS path to store prediction results.
    *   `--model-type`: `regression`, `classification`, or `forecasting` (to handle output parsing).
*   **Core Logic:**
    1.  Initialize `aiplatform.init()`.
    2.  Load the `Model` or `Endpoint` object.
    3.  If using a Model, deploy it to an Endpoint if not already deployed.
    4.  Execute a batch prediction job using `model.batch_predict()` or `endpoint.predict()` for online.
    5.  Process and display/save the prediction results.

### 4.3. `monitor_automl_job.py`

*   **Purpose:** To check the status and retrieve evaluation metrics of an AutoML training job.
*   **Inputs:**
    *   `--job-id`: The ID of the training job to monitor.
*   **Core Logic:**
    1.  Initialize `aiplatform.init()`.
    2.  Retrieve the `TrainingJob` object.
    3.  Report job status (running, succeeded, failed).
    4.  If succeeded, retrieve and display key evaluation metrics (e.g., RMSE, MAE, AU_PRC) from `job.model_to_deploy.model_evaluation`.

## 5. Key Considerations

*   **Dataset Types:** The `vertex_ai_data_transformer_v2.py` script generates three distinct CSVs:
    *   `data_regression_mz.csv`: For AutoML Tabular Regression.
    *   `data_classification_mz.csv`: For AutoML Tabular Classification.
    *   `data_forecasting_mz.csv`: For AutoML Forecasting.
    The `launch_automl_training.py` script must correctly identify and configure the training job based on the `--model-type` and the specific dataset's structure.
*   **Feature Definitions:** The `mfi_str` and `zcol` columns, as identified from the `head` output, are categorical. The `launch_automl_training.py` script must explicitly define these as categorical features during the AutoML training job configuration. Other columns will be inferred or explicitly defined as numeric/timestamp/series identifier.
*   **GCS Paths:** All input and output data for Vertex AI must reside in Google Cloud Storage. The `vertex_ai_data_transformer_v2.py` output will need to be uploaded to GCS before launching training jobs.
*   **Error Handling:** Robust error handling will be crucial for production use.
*   **Region:** Ensure consistency in the Google Cloud region (e.g., `us-central1`).
